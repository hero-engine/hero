# Hero v0.35.1

A patch release with three follow-ups to v0.35.0. There are no workspace,
configuration or schema changes. Replace the binary in place.

## Fixes

- **Delivery-audit staleness no longer misfires after checkout or clone.**
  - Gate 2 used to compare file modification times, which `git checkout`
    and fresh clones rewrite in arbitrary order. When the times suggest the
    audit is stale but the spec and its audit are both committed and
    unmodified, their commit order now decides.
  - Archived specs are exempt, because `hero spec verify` rewrites them after
    their audit. A spec marked `completed` while still in `planning/` is
    still checked.
  - A spec and audit committed together are accepted as one reviewed unit.
- **`hero serve` stops promptly.**
  - A browser's idle preconnected socket used to hold Ctrl+C for 5 seconds
    and end with `context deadline exceeded` (exit 1). Shutdown is now
    immediate and clean.
  - In-flight requests still finish, and live dashboard streams close after
    a 1 s grace.
- **Read contract: epics and containers.**
  - Epics are modelled exactly like initiatives.
  - Initiatives and epics report `verify: null`, because they finish through
    their children. Previously they reported a misleading `not_run` or
    `partial`.
  - This is an additive amendment within `schema_version: 1`; the golden
    schema is unchanged.

## Upgrade

Replace the binary (`brew upgrade hero`). As post-upgrade checks, run
`hero version` and `hero doctor`.
