# Hero v0.35.3

A patch release that closes every note raised by delivery audits since
v0.35.0. There are no workspace, configuration or schema changes. Replace the
binary in place.

## Fixes

- **`hero why --edges` starts from the same node as `hero why`.**
  - When a promoted Mail intake shared its slug with the spec it became,
    `--edges` could start from the intake.
  - It now uses the same resolution as `hero why`, so the spec always wins
    and ties break deterministically.
  - Real database errors are reported as errors, no longer as "no node".
- **Read contract: `open_followups` for items dated by file time.**
  - A recently done item without a `completed_at` date reaches
    `recently_done` through its file modification time.
  - `open_followups` now uses that same completion time, so the item's open
    follow-ups are reported.
- **The audit staleness exemption works with a custom hero folder.**
  - Archived specs are exempt from the delivery-audit staleness check. That
    used to require a folder literally named `.hero`.
  - "Archived" is now decided against the workspace's real hero directory.
    That includes a folder renamed through `"folder"` in `hero.json` or
    `hero.local.json`, and repos checked out beneath a directory named
    `planning` or `specs`.
- **Tests** now cover:
  - CRLF frontmatter in `hero_spec`;
  - knowledge notes that point at an initiative, which are not children;
  - recorded pass/fail acceptance-criteria states;
  - initiative `verify: null` at the tool level;
  - a `hero_work` no-write check across all six watch globs.

## Upgrade

Replace the binary (`brew upgrade hero`). As post-upgrade checks, run
`hero version` and `hero doctor`.
