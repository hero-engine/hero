# Hero v0.34.0 launch checklist

This is the exact handoff from release preparation to the two human-controlled
gates. `PASS` means evidence is resolved. `GATED` is deliberate—not an unknown
or an implicit approval.

## Candidate authority

| Check | State | Evidence / required action |
|---|---|---|
| Latest published baseline is `v0.33.0` | PASS | Candidate builder rejects any other baseline when a newer semantic release tag exists. |
| Target is `v0.34.0` and tag is absent | PASS | Candidate builder rejects a pre-existing target tag. |
| Source identity is exact | PASS | `provenance.json` records the 40-character commit, source tree, commit epoch, Go version, and every artifact hash. |
| Supported archives build twice identically | PASS | Darwin amd64/arm64, Linux amd64/arm64, and Windows amd64 are rebuilt in separate directories and compared byte-for-byte. |
| Checksums, SBOM, and notices exist | PASS | `checksums.txt`, `hero-v0.34.0.cdx.json`, and `THIRD_PARTY_NOTICES.txt` are candidate outputs and are also packed beside each binary where applicable. |
| Native clean-install journey passes | PASS | Extracted local archive runs `--version`, `init`, Codex install, `status`, and `check` with isolated HOME/XDG state. |
| Release notes match public maturity labels | PASS | `v0.34.0-candidate.md` follows the capability-status and claim registries. |

## Expected candidate artifact IDs

- `hero_0.34.0_darwin_amd64.tar.gz`
- `hero_0.34.0_darwin_arm64.tar.gz`
- `hero_0.34.0_linux_amd64.tar.gz`
- `hero_0.34.0_linux_arm64.tar.gz`
- `hero_0.34.0_windows_amd64.zip`
- `hero-v0.34.0.cdx.json`
- `THIRD_PARTY_NOTICES.txt`
- `provenance.json`
- `checksums.txt`

Build from a clean candidate checkout:

```bash
python3 scripts/release_candidate.py \
  --version v0.34.0 \
  --base v0.33.0 \
  --output .build/release-candidate/v0.34.0
```

Manual workflow dispatch runs only this unpublished candidate path. It writes
provenance and checksums to the job summary but uploads no binary artifact. The
publishing job can run only for a `refs/tags/v*` event and fails unless the
final root `LICENSE` and release notices exist.

## Apache grant gate

| Check | State | Required action |
|---|---|---|
| Owner authorizes adding Apache-2.0 to this repository | GATED | Record the explicit approval in `hero-apache-license-grant-gate`. Preparation authority alone is insufficient. |
| Root `LICENSE` contains canonical Apache License 2.0 | GATED | Add only inside the approved license-grant gate. |
| Final notices are present in every production archive | GATED | Promote the reviewed candidate notices to the root release artifact. GoReleaser is already configured to include root `LICENSE` and `THIRD_PARTY_NOTICES.txt`, and the publishing job refuses to run while either is absent. |
| Candidate is rebuilt from the licensed revision | GATED | Re-run the reproducible builder after the license commit; do not publish the pre-license candidate. |

## Public visibility and release gate

| Check | State | Required action |
|---|---|---|
| Repository visibility change is approved | GATED | Record approval in `hero-public-visibility-launch-gate`; run the exposure scan again immediately before the change. |
| Anonymous clone and source links work | GATED | Verify from an unauthenticated environment after visibility changes. |
| Docs and landing deploy the approved revision | GATED | Run their approved deploy workflows and require production revision crawls to pass. |
| Public domains and destinations resolve | GATED | Verify DNS, TLS, canonical docs paths, issue/support pages, installers, and release URLs. |
| `v0.34.0` tag and release publication are approved | GATED | Create the immutable tag only after every preceding gate is green; publish from that exact revision. |
| Homebrew and Scoop resolve the new checksums | GATED | Verify formula/manifests and clean installs from the public channels. |

## Rollback

- Before publication, delete only private candidate workflow artifacts if they
  are superseded; no public rollback is needed because prep creates no tag or
  release.
- After publication, never move the `v0.34.0` tag. If a binary is wrong, stop
  installer promotion, restore channel metadata to the verified `v0.33.0`
  artifacts, mark the affected release clearly, and issue `v0.34.1` from a new
  reviewed revision.
- A repository made public should be treated as disclosed permanently. Making
  it private again can limit new access but cannot revoke clones; the exposure
  scan and secret/history review therefore run before—not after—the visibility
  change.
- If docs or landing revision checks fail, do not route traffic to the stale
  artifact. Restore the last known-good deployment and rerun the exact-revision
  crawl before continuing launch.
