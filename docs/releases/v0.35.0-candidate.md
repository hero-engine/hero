# Hero v0.35.0

Hero v0.35.0 adds the DeepSeek Harness as an install target and a stable
read contract for Hero clients. It also folds in eleven community fixes and a
round of review cleanup.

## Highlights

### DeepSeek Harness target (`--target deepseek`)

`hero install project . --target deepseek` installs the following:
- **Skills:** canonical, `command-*` and `role-*` skills under `.dsh/skills/`.
- **Instructions:** the managed `AGENTS.md` block.
- **MCP:** one Hero MCP server per project, registered in
  `~/.dsh/cordis.patch.yml`. That file is loaded by every DeepSeek profile,
  **including the desktop app**, so no `--patch` flag is needed.

The registration details:
- **Server name:** `hero-<project>-<hash>`.
- **Command:** the absolute path of `hero`, because GUI apps do not inherit
  the shell PATH.
- **Project binding:** `cwd` and `--project-root` are pinned to the project.
- **Safety:** Hero edits only its own marker-delimited block in that file.
  It refuses to write YAML that DeepSeek could not parse.

`hero doctor` reports the registration. `hero uninstall --target deepseek`
removes only that project's entry. Global installs keep a `--patch` overlay.

### Read contract v1: `hero_work`, `hero_spec`, `hero_handoff`

These are three new read-only MCP tools that give any client Hero's
interpretation of the work as stable JSON:

| Tool | Returns |
|---|---|
| `hero_work {recent_days?}` | Every work item with its fields, plus `polish` (loose ends on recent work), `suggested` (deterministic "what next" picks), a content-only `revision` and `watch_globs` |
| `hero_spec {slug}` | One item with its body, relations and acceptance-criteria states |
| `hero_handoff {}` | The `hero next` briefing |

Each work item carries:
- **lane:** `designed`, `ready`, `in_progress`, `recently_done` or `none`;
- **progress** (initiatives);
- **verify state:** derived from audit reports and Completion Ledgers;
- **one next step** as a slash command.

The schema is additive-only within `schema_version: 1`, enforced by a golden
test. `scripts/export-read-contract-fixture.py` exports real replies for
client test fixtures.

### `/verify` workflow

`/verify` is a new slash workflow for every harness target. It runs the cold
delivery audit when one is missing or stale, then `hero spec verify`. Hero's
next step offers it for recently delivered work whose verification is weak.

## Fixes

- **Community contributions** (thank you, davidray and miguelf):
  - #4: `hero.local.json` peer repos are merged into the effective config.
  - #8: Attention Mail is scoped to the querying project.
  - #10 / #11 / #12: `hero mcp` stops leaking `.hero/mcp-*.pid` files. The
    watchdog exit cleans up, stale files are reaped on start, and the files
    are gitignored.
  - #14: Gate 2 delivery-audit identity and staleness checks.
  - #16: worktree-safe, rename-stable peer manifest name.
  - #17: decision and knowledge children count as finished for `/drive` and
    initiative completion.
  - #18: no phantom sibling-harness installs.
  - #20: Completion Ledger sign-off requires a known identity.
  - #21: the digest hint points at `hero search`.
- **Other fixes:**
  - Spec titles no longer keep their YAML quotes in `hero list` and
    `hero_list`.
  - `hero upgrade` refreshes the managed `.gitignore` block, so new entries
    reach existing workspaces.
  - Codex and other harnesses: a same-version `hero upgrade` repairs missing
    generated files, and `hero doctor` flags and names missing files for every
    target.
  - `hero connect aha` saves an Aha! connection usable for raw tracker
    requests only. Issue sync for Aha! is not implemented yet and says so.
  - Fixed a flaky `serve` shutdown test.

## Upgrade

Replace the binary, then run `hero upgrade` in each workspace. It refreshes
generated harness files and the managed `.gitignore` block. To pick up the
home-patch MCP registration, re-run `hero install project . --target deepseek`
in DeepSeek projects.

As post-upgrade checks, run `hero version`, `hero doctor` and `hero check`.
