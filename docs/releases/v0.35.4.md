# Hero v0.35.4

This patch release keeps the `NEXT.md` handoff briefing (and `hero_handoff`)
up to date. There are no workspace, configuration or schema changes. Replace
the binary in place.

## Fixes

- **`NEXT.md` and `hero_handoff` show current spec status.**
  - The briefing is built from Hero's graph cache. Verifying, editing or
    archiving a spec changed only the spec files, never that cache. So
    Next could name a spec that was already complete, and Blocked on could
    list blockers that had already shipped.
  - Every checkpoint (and `hero next project`) now re-syncs specs into the
    cache before building the briefing.
- **Better Next ordering.**
  - Priorities rank `P0`/critical > `P1`/high > `P2`/medium > `P3`/low
    across both naming styles. Before, `low` could outrank `medium`.
  - Critical and high bugs earn the second Next slot.
  - Ties go to the more recently created spec.
- **Just finished lists real work.** It shows the five most recently
  completed specs, then the pointer to `git log`.
- **Clean `hero_handoff`.** `markdown` is now the briefing body only,
  without the managed snapshot block or frontmatter. `updated_at` and a new
  `repo` field carry the metadata. This is additive within read contract v1.
- **`hero next checkpoint` no longer hangs.** A git hook run from an IDE or
  agent tool can inherit a stdin that stays open without sending anything.
  The checkpoint waited on it forever; it now waits at most one second.

## Upgrade

Replace the binary (`brew upgrade hero`). The first checkpoint after
upgrading re-writes every spec node in the graph cache once.
