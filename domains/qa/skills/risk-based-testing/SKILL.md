# Risk-based testing

Describe risks as an unwanted event and consequence, not a component name. Score
likelihood and impact using explicit evidence; use detectability, change exposure,
and recovery cost as tie-breakers. Map high risks to prevention, fast feedback,
deeper functional or nonfunctional testing, and release evidence. State risks the
team accepts or defers. Revisit scoring when scope, architecture, usage, or
production evidence changes.
