# EARS test derivation

Keep the source criterion unchanged and give it a stable reference. Identify its
precondition, trigger, response, and observable result. Create the positive case
first, then add trigger-not-met, precondition-failed, unwanted-behavior, boundary,
and recovery cases only when they distinguish product behavior. If a criterion has
multiple independent responses, split the test conditions while preserving one
traceability link. Flag missing observability or ambiguous language instead of
inventing expected behavior.
