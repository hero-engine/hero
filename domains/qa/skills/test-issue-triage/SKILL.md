# Test issue triage

Verify expected and actual behavior, reproduction evidence, linked requirement,
case validity, environment, history, and whether shipped behavior previously
worked. Choose faulty test when the case or harness is wrong; story rejection when
implementation misses committed acceptance criteria; new bug when independent
product behavior is defective; regression when previously protected behavior broke.
Explain alternatives and ask the human to confirm before creating downstream work.
