# `hero next` vs `hero resume` vs `hero handoff` — Design and History

This note exists because the user asked, mid-session, *"can you dig
up the specifics on next vs resume from previous chats and commits?"*
— and the answer required grepping git log + reading commit bodies +
tracing renames. Capturing it here so the next session never has to
re-derive.

## Current shape (the answer)

Three artifacts/commands in this space, each with a distinct job:

| Command | What it is | Where it writes | When it runs |
|---|---|---|---|
| **`hero next`** | The durable cross-session briefing artifact. **Now graph-projected** (Phase 4) — humans don't write it, the engine does. | `.hero/NEXT.md` (solo) or `.hero/next/<user>.md` (team). Persists. | `hero next checkpoint` runs every turn via host-tool Stop hook. |
| **`hero resume`** (was `hero brief`) | The per-session **digest** — focused/ranked/scored subgraph slice for *this* session. | Stdout → fed into the model's context window. Ephemeral. | At session start. Auto-fired by `/resume` slash command + natural-language triggers. |
| **`hero handoff`** | Older compact session-checkpoint artifact for cross-tool transfer. Largely subsumed by NEXT.md. | `HANDOFF.md` (transfer file: dump → load → delete). | Explicit — when switching tools mid-task. |

**Complementary, not competing:** NEXT.md is the persistent state;
resume is the runtime context bundle. Agent reads **both** at
session start — NEXT.md for human-curated framing (Last user ask,
Next, Blocked on, Tried and failed), resume for the broader
graph-derived slice (recent commits, in-flight specs, dependency
chains, files-nearby).

## Load-bearing design decisions

These are the non-obvious calls that shaped the current design.
Quoted from the original commit bodies where they're the canonical
articulation:

### NEXT.md is graph-projected, not hand-written (Phase 4)

> *"NEXT.md is now generated by querying the unified graph rather
> than hand-written. Same five sections, but they're always fresh
> and consistent with the actual state of the repo."*
>
> *"The 'projections always win' rule is now enforced: hero writes
> NEXT.md, humans don't. Any hand-edits get replaced on next
> render."* — `2158bd2`

The five projected sections:
- **Just finished** → Commit nodes, ordered by date, top N
- **Next** → open Feature nodes by priority then recency
- **Blocked on** → Feature `─depends_on/blocks→` non-completed nodes
- **Tried and failed** → Attempt nodes attempted_in current Session
- **Context to carry forward** → top open Decision/Initiative nodes

(The current `.hero/NEXT.md` is a hybrid because the agent half is
still being written manually until `project-charter` ships. The
direction is full projection.)

### `hero resume` is the per-turn injection (Phase 5)

> *"Hero's reason for existing: make every LLM turn smarter from
> the history of every prior turn. The graph substrate built in
> phases 1–4 was preparation; this phase delivers it to prompts."*
>
> *"The principle: infinite capture, finite (but not strictly
> limited) delivery. The graph holds everything; the brief
> surfaces a focused, ranked, scored slice tailored to who's
> working, in this repo, on this branch, with these files
> dirty."* — `0c79b34`

Scoring formula: `recency_decay × focus_match × signal_weight`,
half-life 30 days. Soft target 3000 tokens; sections may grow up
to 2× target when candidates earn it; hard cap 4×. Truncated
sections emit a *"+N more — `hero search <topic>` to dig deeper"*
hint — natural-language relief valve.

### Agent never writes the machine half

A host-tool Stop hook runs `hero next checkpoint` every turn,
keeping the machine block (branch, recent commits, working tree,
hot files) fresh. **Agent only writes the agent half** — and only
when the objective triggers fire:

1. Files modified
2. Git commit made
3. Spec status changed
4. Next task changed
5. Design decision made
6. Test/build failed
7. >3 turns since last update (force refresh)

Plus the user-side trigger (intent shifted, approach failed).

### User-facing names match user intent, not implementation

> *"The user-facing intent is always 'warm me up so I can pick up
> working' — whether or not a handoff exists is implementation
> detail. `hero resume` becomes the canonical warm-up command...
> commands/brief.md slash-command collapses into
> commands/resume.md with an expanded 'What to say' trigger list
> — agents auto-route natural-language requests ('let's continue',
> 'where are we', 'catch me up') to /resume without users having
> to know the command name."* — `0852de2`

This is principle #2 ("natural language is the interface; tools
are the escape hatch") in action. The same principle drove
`recall→search` and `nudge→relevant` in the same commit family.

### `/resume` auto-fires on natural-language triggers

The `core/commands/resume.md` slash-command file lists the trigger
phrases agents should auto-route to `/resume`:

> *"resume", "let's resume", "let's continue", "continue", "pick
> up where we left off", "where are we", "what's going on", "catch
> me up", "load context", "load up", "load me up", "starting
> fresh", "fresh session", "hot session", "warm me up", "what
> should I work on", "what's the status", "give me the lay of
> the land".*

User never has to know the command name. They describe intent.

### Solo vs team mode is a config call

`hero.json` has `next.mode: "solo"` (default) or `"team"`.

- Solo: one shared `.hero/NEXT.md`
- Team: per-user `.hero/next/<user>.md` + a shared `.hero/NEXT.md`
  roster line

`hero next path` returns the right path for the active mode so
agents don't have to figure it out.

## Why this matters for the recovery

The user's question proved the mission test: *"can you dig up the
specifics?"* required grep + read + commit-body archaeology. With
proper Tier-2 extraction from `master-ingest-restore`, the same
question would be `hero why hero-resume` — traversing edges
between `Decision` (the rename), `Note` (this note), `Spec`
(graph-memory phase 5), `Commit` (`0852de2`), and back to the
originating discussion.

The corpus *has* the answer. Today retrieval requires manual
work. After master-ingest + AC-graph land, this exact recall
becomes one command.

This note itself is the dogfood: the next session asking the same
question reads this file and gets the answer in one read,
preserving the iteration cost.
