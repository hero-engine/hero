## Audit notes

- **HOME-isolation seal verified empirically, with one confounder resolved.** Snapshotted the real `~/.codex/config.toml` before running `go test -race -count=1 ./internal/install/ ./internal/cli/` (both `ok`, 3.8s / 54.9s). Afterward the file's mtime had advanced and one line differed — `last_updated` under `[marketplaces.openai-primary-runtime]`, bumped exactly 3 hours (04:31:54Z → 07:31:54Z) at a wall-clock time matching the file mtime. That is the running Codex desktop app's own periodic marketplace refresh, not a test write: nothing in Hero writes `marketplaces`/`last_updated` TOML keys, and a leaked Hero test write would have re-pointed `command` at a transient go-test binary under `/var/folders` (it still points at the repo binary; exactly one hero block; every other byte identical). The seal holds.
- **Workspace-mode exception (delivery note) judged sound, but it is a deviation from the letter of the decided design.** Fix Direction item 1 says the User layer wins "on both project and global installs"; workspace mode (`opts.ProjectRoot != ""`, set only by `hero install ... --workspace`, `internal/cli/install.go:394`) keeps writing the workspace's own `.codex/config.toml`. The reasoning holds: the `--project-root` arg pins the MCP server to one repo, so a User-layer copy would deep-merge into **every** Codex session on the machine and pin them all to that repo; Codex's Project layer (precedence 25 > User 20) overriding per-key is the correct home. Residual: the workspace file still carries a machine-specific absolute binary path — but the `--project-root` value is an absolute machine path anyway, so workspace configs are inherently machine-specific; the fix cannot and does not change that.
- **Dogfood User-layer command points at a dev-build artifact** (`<repo>/hero`, the binary that ran the install). Correct by design (os.Executable of the installer); if that build artifact is later deleted, Codex's MCP startup will fail visibly until re-install. Inherent to the decided design, not a defect.
- **`.mcp.json` (claude) still carries the stale `/Users/developer/go/bin/hero` absolute path** — explicitly out of scope per the spec; the shared-resolver fix means the *next* claude install rewrites it correctly.
- Validation run by this audit: `go build ./...` clean; both suites pass under `-race -count=1`; all 8 named new tests pass under `-v` (12 including subtests). The ledger's full-`./...` claim was not independently re-run (out of the audit's requested scope).
- Diff is well-scoped: beyond the spec's named files, only `.hero/NEXT.md`, `.hero/next/chet-bellows.md`, and the spec itself changed (projected handoff files that travel with the commit — expected).
