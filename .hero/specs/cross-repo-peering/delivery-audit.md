## Gaps and Observations

### PARTIAL items (both are by design, not oversights)

1. **Manifest `contracts:` (Shapes) not auto-populated.** `GenerateManifest()` leaves `Shapes` empty. The spec itself pins this as an open question for Phase 4 with three explicit options (auto-discover, hero.json hand-author, manual maintenance). The "do not hand-edit" comment in the generated manifest is a known forward-looking claim, not a broken promise in v1.

2. **Integrity explicit wiring deferred.** `IsLocallyDelivering()` documents the contract; a `TODO` in `spec.go` tags the coordination point. The `spec-status-integrity` spec owns the explicit invariant check; until it lands, handoff statuses are implicitly excluded because the integrity package only checks `completed` specs. This is the correct sequencing — cross-repo-peering defines the contract, spec-status-integrity consumes it.

### Not-found items (spec items that resolve to different actual paths)

3. **`agents/feature-delivery-lead.md` peer-call routing sections.** The spec listed this as a modified file. The agent at `domains/engineering/agents/feature-delivery-lead.md` does not have explicit peer-handoff/peer-call routing sections. This content is covered by the new `domains/engineering/commands/peer.md` slash command and `domains/engineering/skills/cross-repo-peering/SKILL.md`. The routing intent is satisfied via the command+skill pair; the agent itself does not need inline sections to achieve the goal.

4. **`skills/convention-writing.md` peer-surface subsection.** The spec listed this as a modified file. The `domains/engineering/skills/convention-writing/SKILL.md` does not contain a "peer-surface" subsection. This content lives in the cross-repo-peering SKILL.md under "Convention import (fallback)." The split is reasonable — convention-writing is a general skill; the peer-specific surface guidance belongs where the feature is defined.

### Safety review

- No secrets, credentials, or outpost content referenced in any peering file — confirmed by absence of `outposts` imports in `internal/peering/`.
- Receiver-first write order in `Handoff()` is documented and surfaces via `hero check` on partial failure.
- Advisory mode no-write contract is in code, not just in prompt — `Call()` validates mode before spawning subagent.
