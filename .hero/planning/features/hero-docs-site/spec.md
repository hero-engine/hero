## Goal

Publish the docs that live in this repo (and `mkdocs.yml`) as a hosted,
searchable site at a stable URL — `docs.heroengine.ai`. New
users should find their answer in under three clicks; advanced users
should be able to grep the entire reference.

## Problem

`mkdocs.yml` and the `docs/` folder already exist, but the site isn't
published. Today's onboarding is the README — useful but linear, hard
to deep-link, and missing the reference depth (every command, agent,
skill, MCP tool, config option).

Docs aren't just for support tickets. They're a sales surface: every
deep-link in a tweet, blog post, or HN comment that resolves to a
specific docs page is a free re-pitch of the product.

## Tech choices

- **Generator**: keep `mkdocs` with the `material` theme — it's already
  set up, has good search, dark mode, and copy-button code blocks. Don't
  switch to Docusaurus / Nextra unless there's a concrete reason.
- **Hosting**: Cloudflare Pages connected to the private GitHub repo.
  Free, unlimited bandwidth, native PR previews, single dashboard with
  the Cloudflare DNS that already fronts the domain.
- **CI**: Cloudflare Pages builds on every push to `main` and on every
  PR (preview deployment). No separate GitHub Actions step needed.
- **Search**: built-in Material search is fine for v1. Algolia DocSearch
  if it gets bigger.
- **Versioning**: `mike` for versioned docs once we cut a v1.0 — defer
  for now, ship `latest` only.

## Content sourcing

Existing material to migrate:
- `README.md` → `/quickstart` + selected reference
- `GETTING-STARTED.md` → `/workflows/new-project`
- `MCP-SETUP.md` → `/integrations/opencode|cursor|claude-code|copilot`
- `AGENTS.md` → `/concepts/agents` + per-agent reference pages
- Existing `agents/`, `commands/`, `skills/` markdown → autogenerated
  reference pages (one per file)
- `.hero/planning/initiatives/*/spec.md` → public roadmap page (curated)

Net new content (one paragraph each, build over time):
- `/concepts/*` — five concept pages
- `/workflows/*` — six recipe pages
- `/guides/*` — three opening guides; rest seeded for the content engine

## Generated reference pages

A docgen script (`make docs-gen` or a small Go program) walks
`agents/`, `commands/`, `skills/` and produces a markdown page per file
under `docs/reference/`. The page uses the file's frontmatter
(name, description, tags) plus the body. Re-runs are idempotent. Run on
every CI build so reference never drifts from source.

## Acceptance criteria

- `docs.heroengine.ai` resolves with HTTPS
- Search works across all pages
- Quickstart leads to a working install + first spec in < 5 minutes
- Every CLI command, slash command, agent, skill, and MCP tool has a
  reference page
- Every reference page has a stable URL we can deep-link from blog/tweets
- Build and deploy run from `main` automatically; PR previews available
- Lighthouse 95+ on perf, 100 on accessibility

## Out of scope

- Versioned docs (defer to v1.0 cut)
- Multi-language localization
- API reference for the daemon HTTP API (separate effort, low demand)
- Inline runnable code samples (defer)

## Decisions

- **Domain**: `docs.heroengine.ai` (parent domain `heroengine.ai` purchased 2026-05-14). Supersedes earlier `docs.teamhero.cloud` plan; see `.hero/knowledge/decisions/domain-name.md`.
