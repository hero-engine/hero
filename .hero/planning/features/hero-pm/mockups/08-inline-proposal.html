Roadmap Agent Observability › Epic Telemetry & traces › Story 2849

As a Hero runtime I need to inject W3C traceparent headers into downstream HTTP calls so customer APMs join our spans into their traces.

refined high Cycle 14 · 2w
MJ
Marcus Johnson HERO-2849 ↗ #telemetry #sre

Downstream services running customer APM (Datadog / Honeycomb / Tempo) accept the W3C trace-context standard. If the agent runtime injects a traceparent header on every outgoing HTTP call, customer's existing trace ingestion picks up the parent-child relationship for free — no Hero-specific integration needed on their side.

Scope: outgoing HTTP from the agent runtime (HTTP-tool calls, LLM-provider calls, webhook callbacks). Out of scope: outgoing gRPC, message-queue producers, raw socket I/O.

Acceptance criteria · current

  • WHEN the agent runtime makes an outgoing HTTP request THE SYSTEM SHALL inject a traceparent header conforming to W3C trace-context v1.
  • WHEN a tool call already supplies a traceparent THE SYSTEM SHALL preserve the upstream context and use it as the parent.

Proposed by story-writer · 3 acceptance criteria · just now

accepted · story-writer
WHEN an outgoing HTTP request is to a non-HTTPS endpoint THE SYSTEM SHALL still inject the traceparent header (no security restriction — W3C spec applies to all schemes).
edited by Marcus · proposed by story-writer
WHILE the OTLP exporter is unavailable THE SYSTEM SHALL continue to inject traceparent headers using a synthetic root span ID until export resumes — header injection MUST NOT be coupled to span flush state.
⏎ to accept · ⌘Z to revert
proposed by story-writer · just now
IF a downstream service responds with a traceresponse header THEN THE SYSTEM SHALL record the returned trace ID as a span attribute (downstream.trace_id) on the parent span.
