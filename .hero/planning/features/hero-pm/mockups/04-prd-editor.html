Agent observability — give SREs the trace surface their APM tools already speak.

review high 6w appetite
SC
Sarah Chen HERO-PRD-44 ↗ 4 stories

Problem # problem

SREs operating Hero-deployed agents in production have no way to correlate an agent run with the downstream services it called. When a payment-flow agent triggers a 502 on a billing webhook, the on-call has run-level logs in Hero and HTTP logs in Datadog — but no shared identifier joining them.

"Last week I spent 90 minutes manually cross-referencing timestamps to figure out which agent run caused our checkout latency spike. We have OTLP everywhere else. Why not here?" — Priya R., SRE @ Mintwave, 2026-05-03 customer interview

Appetite # appetite

6 weeks. One Cycle 14 bet. If the OTLP exporter is not flushing real spans into a customer's APM by end of Week 5, we cut scope (drop the buffering-on-failure path) before extending.

Solution sketch # solution

Emit OpenTelemetry-compatible trace spans from the agent runtime. Each run = one root span; each tool call = one child span; outgoing HTTP calls inject W3C traceparent headers so downstream services tie back automatically.

  • Runtime-level exporter (OTLP gRPC) — configurable endpoint via HERO_OTLP_ENDPOINT
  • Span shape: run.id, run.session, tool.name, tool.duration_ms, tool.outcome
  • Customer's APM (Datadog / Honeycomb / Grafana Tempo) renders the trace tree natively

Rabbit holes # rabbit-holes

  • Building our own trace viewer. Customer's existing APM does this well; building one in Hero is a 3-cycle bet, not a 1-cycle one.
  • Schema universalism. Don't try to invent a span schema that handles every agent framework. Ship Hero's schema; document the W3C contract for headers; let other vendors map.
  • Cardinality explosion. Tool-call attributes (especially LLM-call inputs) can blow up cardinality fast. Decide on attribute allow-list early.

No-gos # no-gos

  • No Hero-native trace storage. We're an emitter, not a backend.
  • No replacing the existing structured-logging path. Both run in parallel for v1.
  • No prompt-level span content (privacy + cardinality). Tool inputs are summarized, not captured raw.
