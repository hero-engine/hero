Roadmap Agent Observability › Epic Telemetry & traces › Story 2847

As an SRE I need agent runs to emit structured trace spans so I can correlate them with downstream service latency.

ready high Cycle 14 · 2w
MJ
Marcus Johnson HERO-2847 ↗ #telemetry #observability #sre

Today, when an agent run misbehaves in production, the on-call SRE has no way to correlate the run with the downstream services it called. We log run-level events, but they don't share an identifier with the HTTP requests, queue messages, or LLM-provider calls the agent triggered downstream.

The fix is OpenTelemetry-compatible trace spans emitted from the agent runtime. Each run becomes a root span; each tool call becomes a child span; each downstream HTTP call inherits the run's trace context. Existing customer APM tools (Datadog, Honeycomb, Grafana Tempo) pick this up for free.

Out of scope for this story: a Hero-native trace viewer. We'll wire the emitter and document the integration; visualization happens in the customer's existing APM. If demand emerges, a separate roadmap-item will pick that up.

Acceptance criteria · EARS

  • WHEN an agent run starts THE SYSTEM SHALL emit a trace span with run-id and parent-session-id.
  • WHILE a run is active THE SYSTEM SHALL emit child spans for each tool call, including tool name and duration.
  • IF a span fails to flush THEN THE SYSTEM SHALL retry with exponential backoff (max 3 attempts) before dropping.
  • WHEN downstream HTTP calls are made THE SYSTEM SHALL inject W3C traceparent headers automatically.
  • IF OTLP endpoint is unreachable for > 60s THEN THE SYSTEM SHALL log a single degraded-mode warning and buffer up to 10k spans in memory.
