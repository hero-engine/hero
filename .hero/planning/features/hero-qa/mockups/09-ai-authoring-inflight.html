C5 Verify retry max_attempts boundary (off-by-one safety) AC#1 · negative / boundary
Type · scripted · boundary-value · Format · step-by-step
#
Do
Expect
1
Set max_attempts = 1 (lower bound). Trigger flaky tool.
Exactly 1 attempt — no retry; run terminates with tool-failure.
2
Set max_attempts = 10 (upper bound). Trigger always-failing tool.
Exactly 10 attempts observed in span; 11th attempt does not occur.
3
Inspect retry interval sequence at max_attempts = 10.
Sequence respects initial_delay_ms × 2^n capped at max_delay_ms.
4
Compare attempt count emitted in trace span vs. retry log.
Span attribute retry.attempt_count equals log entry count exactly.
i
This case uses boundary-value derivation from AC#1's max_attempts ≤ 10 constraint. It guards against the off-by-one regression class that has hit retry logic twice (see RC-318, RC-402).
