Description read-only · PM-owned

Today, when an agent run misbehaves in production, the on-call SRE has no way to correlate the run with the downstream services it called. We log run-level events, but they don't share an identifier with the HTTP requests, queue messages, or LLM-provider calls the agent triggered downstream.

The fix is OpenTelemetry-compatible trace spans emitted from the agent runtime. Each run becomes a root span; each tool call becomes a child span; each downstream HTTP call inherits the run's trace context.

Acceptance criteria · EARS 5

  • WHEN an agent run starts THE SYSTEM SHALL emit a trace span with run-id and parent-session-id. AC#1 · C1 ✓
  • WHILE a run is active THE SYSTEM SHALL emit child spans for each tool call, including tool name and duration. AC#2 · C2 ✓
  • IF a span fails to flush THEN THE SYSTEM SHALL retry with exponential backoff (1s, 2s, 4s — max 3 attempts) before dropping. AC#3 · C3 ✗ / C4 ✓
  • WHEN downstream HTTP calls are made THE SYSTEM SHALL inject W3C traceparent headers automatically. AC#4 · C1,C2 ✓
  • IF OTLP endpoint is unreachable for > 60s THEN THE SYSTEM SHALL log a single degraded-mode warning and buffer up to 10k spans in memory. AC#5 · C5 ✓
