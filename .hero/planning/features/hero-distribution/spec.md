## Goal

Make installing Hero a one-liner anyone can paste, on any platform a
trial user might be on. Cover macOS, Linux, and (lightly) Windows. Make
upgrades equally trivial. Make releases boring — `git tag` and walk away.

## Problem

Today's install paths:
- `make install` — requires Go toolchain, builds from source
- `brew install hero-engine/tap/hero` — works, but personal tap signals
  "weekend project", not "thing companies adopt"
- No `curl … | sh` for non-Homebrew users
- No `npm i -g`, no `pip install`, no `go install` story we're proud of
- No prebuilt binaries on the GitHub releases page (or they exist but
  aren't documented)

A non-trivial fraction of trial users will bounce on install friction
alone. Every additional command, prerequisite, or unclear next step is
a leak in the funnel.

## Distribution channels

### Homebrew (macOS + Linux) — primary

- Move from `hero-engine/tap/hero` to a project-named tap:
  `hero-cli/tap/hero` or similar, owned by an org we control
- Formula is generated by `goreleaser` on tag push (already partially
  set up — see Makefile / `make release`)
- Document `brew install hero-cli/tap/hero` and `brew upgrade hero` as
  the canonical macOS path
- Submit to homebrew-core once we hit the eligibility bar (notable,
  stable, ≥ 30 GitHub stars, etc.) — keep tap as backup

### Install script (Linux + macOS) — secondary

- `curl -fsSL https://heroengine.ai/install.sh | sh`
- Detects OS + arch, downloads the right binary from the latest GitHub
  release, verifies checksum, drops it in `~/.local/bin` or `/usr/local/bin`
- Source lives in `scripts/install.sh` in this repo, served from the
  landing page with `Content-Type: text/x-shellscript`
- Includes `--version v1.2.3` and `--prefix /opt/hero` flags
- Includes uninstall path: `hero uninstall self`

### GitHub Releases — backbone

- Every tag triggers `goreleaser`:
  - Builds darwin-amd64, darwin-arm64, linux-amd64, linux-arm64
    (Windows experimental)
  - Generates SHA256 checksums + `.sig` for cosign verification
  - Uploads tarballs + checksum file
  - Updates Homebrew formula
  - Generates changelog from commits + spec retros
- Release body links to the changelog page on the docs site

### Container image — tertiary

- `ghcr.io/hero-cli/hero:latest` — minimal Alpine + binary, useful for
  CI runners and serverless agents
- Built by goreleaser on tag

### Other ecosystems — defer

- npm wrapper (`@hero/cli`) — useful for JS-heavy teams; defer to v1.1
- pip wrapper (`hero-cli`) — defer
- `go install github.com/hero-engine/hero/cmd/hero@latest` — already works,
  just document it under "From source"

### Windows — experimental

- Provide a windows-amd64 binary in releases
- No installer / scoop / chocolatey — point users at `scoop install` if
  they want it, contributions welcome
- Note "Windows is best-effort" in docs until we have time to invest

## Release flow

```
git tag v1.2.3 && git push origin v1.2.3
   ↓
GitHub Actions runs goreleaser
   ↓
Builds binaries, signs, uploads to GitHub Releases
   ↓
Updates homebrew tap formula via tap repo PR
   ↓
Pushes container image to ghcr.io
   ↓
Posts changelog to #releases (community channel) and to RSS at heroengine.ai/releases.xml
```

Tags follow semver. We write a `RELEASING.md` covering: version bump
checklist, breaking-change policy, deprecation window, hotfix process.

## Auto-update

- `hero version` shows current vs latest (already partially implemented
  in `internal/version/`)
- Once a day, the daemon (`hero serve`) checks for updates and surfaces
  a one-line nudge in the next CLI invocation
- `hero update` — wraps `brew upgrade hero` or re-runs the install
  script depending on how Hero was installed
- All update checks honor a `HERO_UPDATE_CHECK=0` opt-out

## Acceptance criteria

- `brew install <tap>/hero && hero --version` works on a clean macOS
  machine in one command
- `curl -fsSL https://heroengine.ai/install.sh | sh && hero --version` works
  on a clean Ubuntu container in one command
- `hero update` upgrades to latest regardless of install path
- Every release has signed checksums and a `cosign` verification example
  in `RELEASING.md`
- Tag push → release published → tap updated → image pushed in ≤ 5 min
  with no human steps
- The docs site has a single "Install" page that branches by OS

## Security

- Sign all release tarballs with cosign + GitHub OIDC (keyless)
- Publish provenance via SLSA Level 3 if reasonable
- `install.sh` verifies SHA256 against published checksum before
  executing the binary
- No silent telemetry inside the install script — telemetry is a
  separate, opt-in concern (see hero-telemetry)

## Out of scope

- Paid distribution (App Store, Setapp, etc.) — defer indefinitely
- Auto-rollback on a bad release — defer; mitigate via slow rollout
  for homebrew-core when we get there
- Per-user license keys — no paid product yet
