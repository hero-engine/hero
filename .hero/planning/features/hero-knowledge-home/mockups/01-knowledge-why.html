Decision accepted inline-propose-approval-model Jul 2025

Approval gate for inline-propose outputs

Context

/deliver sessions emit file diffs through the inline-propose shim. Some edits are obviously safe (formatting, comment fixes); others mutate behavior. We need a model for when the daemon applies a proposal automatically and when it pauses for a human gate.

Options considered
  • AAlways require human approval. Safest but kills the autonomy ratio.
  • BTiered gate: auto-apply read-only + scoped writes; gate behavior-affecting edits.chosen
  • CAuto-apply everything, snapshot for rollback. Too costly to unwind in shared workspaces.
Consequences

approveProposal() becomes the single chokepoint. The decision establishes the idempotent-server-mutations convention so re-deliveries of the same proposal don't double-apply. Future tiers (silent vs. notify vs. block) plug into the same gate.
