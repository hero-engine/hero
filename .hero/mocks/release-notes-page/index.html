v0.24.1 ¶

Jul 9, 2026 Latest

Major Features ¶

  • Add hero next install-hooks to auto-stage projected handoff files (NEXT.md, .hero/next/*.md) on every commit, closing the gap where handoff state silently drifted from committed history.
  • Introduce graph-backed hero why traversal — trace any spec, decision, or commit back through the chain of relations that produced it, multi-hop, from a single CLI call.
  • Ship the hero peer surface (peer list, peer show, peer call) for cross-repo advisory questions and spec-out delegation between sibling Hero workspaces.
  • Add the hero_search MCP tool's compact mode — single-line existence checks instead of full excerpt dumps, cutting agent context usage on routine lookups.

Fixes ¶

  • Make NEXT.md projection deterministic from committed graph state — repeated runs on a clean checkout no longer produce diffing output.
  • Give smoke test scripts the built binary and a populated graph fixture, fixing false-negative failures on fresh CI runners.
  • Fix events.log merge conflicts on concurrent branches by adding a merge=union git attribute driver.

v0.24.0 ¶

Jul 2, 2026

Major Features ¶

  • Launch Graph Memory — a unified substrate backing specs, knowledge, decisions, and events behind one queryable corpus, replacing the previous flat-file indexes.
  • Add hero_context and hero_relevant MCP tools so delivery agents can pull ranked, related prior work into a session automatically, without a manual search step.
  • Support configurable workspace location — .hero/ no longer has to live at repo root; point it anywhere via hero.json.

Fixes ¶

  • Fix hero drift reporting stale conventions as current when a spec was archived out of .hero/planning/ without updating its relation edges.
  • Harden CLI test isolation so a stray .hero/ workspace on the host machine no longer leaks into sandboxed test runs.

v0.23.2 ¶

Jun 24, 2026

Fixes ¶

  • Fix hero sync pull throwing on Jira issues with an empty priority field instead of defaulting to P3.
  • Fix a race in hero_kickoff where two agents claiming the same spec within the same second could both succeed.
  • Correct hero snapshot risk counts double-counting specs that appear in both blocked and at-risk buckets.

v0.23.0 ¶

Jun 11, 2026

Major Features ¶

  • Add the Team Server — a shared job queue and approval-gate coordination layer so multiple engineers can drive the same initiative without stepping on each other's claims.
  • Add hero handoff and hero handoff accept for async cross-repo spec transfer between sibling Hero workspaces, with full audit trail.
  • Introduce Retrieval Contradiction Detection — hero ask now surfaces when a retrieved fact conflicts with a more recent commit or spec, instead of silently returning stale context.

Fixes ¶

  • Fix hero_verify MCP tool timing out on specs with more than 40 acceptance criteria instead of chunking the request.
  • Fix nav sidebar in the docs site failing to highlight the active section after a client-side route change under navigation.instant.

v0.22.0 ¶

May 28, 2026

Changes ¶

Published before grouped changelogs were enabled — rendered as a single fallback section per the spec's Boundaries.
  • Add hero scan deep-enrichment pass for auto-generated symbol descriptions across large codebases.
  • Fix hero import pagination cutting off after 100 tracker issues on GitHub-backed projects.
  • Add hero.json validation on hero check to catch malformed tracker config before a sync attempt fails mid-run.
  • Fix stale hero_active results after a spec's status changed via direct tracker sync rather than the CLI.
