**Five stability points we're implicitly depending on — please treat these as contract, not implementation detail:**

a) **Port-printing on `--port 0`.** `offline_suite.sh:36` greps `:PORT` from the process's combined stdout+stderr. A machine-readable log line at startup (e.g. `listening: http://127.0.0.1:$PORT`) or a `--port-file` flag would be more robust than the current regex — but the current parse works today; only flag if the log format is about to churn.
b) **Per-mode base_url mount layout.** `$BASE/github`, `$BASE/gitlab`, `$BASE/jira`, and `$BASE/linear/graphql` (Linear is the exception — the client posts GraphQL directly to `base_url`, so it must include the `/graphql` suffix). Keeping this mount layout keeps `hero.json` writeable per-mode without any adapter branching.
c) **`/__admin/mutate` shape.** `POST /__admin/mutate` with `Authorization: token $MOCK_TOKEN`, JSON body `{"id":"<global_id>","field":"<name>","value":"<string>"}`. The suite reads the mutated state back via the tracker's own read endpoint, so no admin read is required.
